均为完整第五轮 A 学生、standard 三相机、Kit 16 线程、物理 2 线程；后四项注册 renderer descriptors 360000/900000。M 是视觉微批量。控制阶段包含循环、numeric flush、trace 压缩和推理计数校验，不包含初始化和模型装载；异步 GPU 阶段显式同步。CPU8 的 M2 不是已完成 collection07 的 M8 配置，不能用此行推断实际 collection07 的速度。

GPU16 的 15 条合法轨迹都曾接触物体、都曾在同一控制步的两次物理采样中保持至少双指接触；其中 lane 3、5、8、14、15 曾连续 12 步双指接触且高于其已完成 25–48 步的物体高度中位数 2cm。只有 lane 3 满足旧拿稳窗口。原生抬升、原生靠近目标、对准和首子目标均为 0；这与上述持物条件不同。lane 6 在执行前被保守碰撞界限拒绝，0 个学生步，保留这次失败，不重跑。GPU8 也拒绝了 lane 6。

所有实际执行 lane 的三相机有效标记、新帧、观测/transition 时间连续性、60Hz 间隔、有限 29 维目标、每步两次物理目标及完整 DP/后端计数通过逐条检查。实际物理目标与提交的绝对目标一致。原生插入阈值仍为 15mm。这里的 camera_valid 来自现场真实 RGB-D 检查；短 probe 没有另存完整图像。36 步只到 0.6 秒，尚无接触，也不足以形成 25–48 步高度参考；180 步为 3 秒，仍然不是完整任务或完整专家救回验收。所有成功字段都是 diagnostic，不计自主成功率。

建议下一批使用 CPU standard、16 lanes、M8，让第一完整 wave 经过已有真实学生前缀、专家续接、HDF5 校验及入池检查；已验收的 CPU8 保留回退。CPU32 的本次控制吞吐较 CPU16 低约 9%，初始化约 4.45 倍，暂无采用依据。GPU16 已通过接触阶段的部分验收，但需先完成一次完整专家续接及真实数据准入，再决定扩大。180 与 36 步的工作量、合法 lane 数和物理 RNG 不同，不能把 24.76/21.76 宣称为公平 GPU 加速比。

64 环境第一次在实际文件描述符限制 2450 附近发生 `Too many open files`，由操作记录保全后终止。第二次单作业申请 65536 文件描述符，日志不再出现该错误，但仍出现 `ProjectedAreaCullingData::PerViewState` GPU slot 申请失败，最终在预登记初始化时限后退出，0 个动作。两次日志及 owner 状态有 SHA256 绑定。它们证明这些具体配置未通过初始化，不能据此设通用 32/64 环境硬上限；也不能算已验证 64 环境吞吐。
